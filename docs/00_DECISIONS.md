# 00. Ревью концепции и архитектурные решения (ADR)

Документ фиксирует слабые места исходной концепции «My Personal Tutor» и принятые решения.
**Для агентов это обязательные правила.** Изменить решение можно только через новый ADR
(агент `architect`), с обновлением этого файла и затронутых спецификаций.

Формат: *Проблема* → *Решение* → *Последствия*. Статус всех ADR ниже — **Принято**, если у ADR не указан иной статус.

## ADR-01. Стек и целевые платформы

**Проблема.** Требование «кроссплатформенность» не уточнено, а мобильная экосистема Tauri 2
(плагины, отладка, WebView-различия) заметно беднее десктопной.

**Решение.**
- Tauri 2 + Svelte 5 (runes) + TypeScript (strict) + Vite + Tailwind CSS v4 + Bits UI.
- Фронтенд — **SvelteKit в режиме SPA** (`adapter-static`, `ssr = false`) — рекомендованный Tauri путь.
- MVP: **Windows, macOS, Linux**. Android и iPadOS — Фаза 8.
- Уже с Фазы 0 код ядра не использует десктоп-only API напрямую: всё платформенное (секреты,
  TTS, файловые диалоги) — за трейтами с реализациями по платформам.

**Последствия.** Мобильная сборка не блокирует MVP, но архитектура к ней готова.

## ADR-02. Cargo workspace: ядро отдельно от Tauri

**Проблема.** Если вся логика живёт в `src-tauri`, её нельзя переиспользовать в компиляторе
курсов (CLI) и неудобно тестировать без запуска приложения.

**Решение.** Workspace из крейтов:

| Крейт | Назначение | Зависит от Tauri |
|-------|-----------|------------------|
| `mpt-core` | доменные модели, парсер, токенизатор, валидатор, проверка ответов, SRS-обёртка, распознаватель | нет |
| `mpt-storage` | SQLite, миграции, репозитории | нет |
| `mpt-importer` | безопасная распаковка, установка и обновление курсов | нет |
| `mpt-services` | TTS-каскад, LLM-клиенты, кэши (feature-gated) | нет |
| `mptc` | CLI-компилятор курсов (`check`, `build`, `align`, `watch`) | нет |
| `src-tauri` | тонкий адаптер: команды, состояние, плагины, capabilities | да |

**Последствия.** Один и тот же токенизатор/валидатор используется и при сборке курса, и в
приложении. `src-tauri` содержит только «клей»; бизнес-логика покрывается `cargo test` без GUI.

## ADR-03. Двухстадийный формат курса: исходники → скомпилированный пакет

**Проблема.** Чистый JSON неудобно писать руками (верно отмечено в исходном документе), но
парсить Markdown в рантайме на фронтенде — это дублирование логики, ошибки обнаруживаются
только у ребёнка, а не у автора.

**Решение.**
1. **Исходники курса** (для людей): `course.yaml`, `lessons/*/lesson.md` (Markdown с атрибутами и
   блоками), `lexicon/*.yaml`, `quiz.yaml`, `exams/*.yaml`, медиа в любых форматах.
   YAML выбран для метаданных, потому что его проще писать руками, чем JSON.
2. **Компилятор `mptc`** валидирует, токенизирует, выравнивает аудио, перекодирует медиа,
   считает хэши и собирает **пакет `.mpt`** (zip) с JSON-AST уроков.
3. **Приложение импортирует только скомпилированные пакеты** и рендерит готовое дерево токенов.
4. Для авторов — dev-режим «открыть папку исходников» (Фаза 2, T-203): то же ядро компилирует на лету.

Полная спецификация: `docs/02_COURSE_FORMAT.md`.

**Последствия.** Ошибки контента ловятся при сборке (`file:line:col`), фронтенд упрощается,
формат версионируется (`format_version`), а JSON Schema генерируется из Rust-структур (`schemars`).

## ADR-04. Синтаксис инлайн-разметки и формулы

**Проблема.** `{w:knight|hl:blue}` конфликтует с ячейками таблиц GFM (`|`), а разметка внутри
`$...$` не является валидным LaTeX.

**Решение.**
- Атрибуты в стиле Pandoc/markdown-it-attrs: `[knight]{w=knight hl=blue}`, значения с пробелами
  в кавычках: `{note="читается без k"}`.
- Блочные контейнеры: `::: reading {audio=audio/story.wav}` … `:::`.
- Цвета подсветки — **именованные токены палитры** (`blue`, `green`, `orange`, `purple`, `red`),
  а не hex: тема, тёмный режим и палитра для дальтоников управляются приложением.
- Кликабельные части формул: `$E_k = \frac{\htmlData{t=mass}{m} v^2}{2}$`. KaTeX запускается с
  `trust`, разрешающим **только** команду `\htmlData`. Компилятор проверяет, что ID существуют.

**Последствия.** Разметка подсвечивается в редакторах, таблицы и формулы не ломаются.

## ADR-05. Стабильные ID токенов и выравнивание таймкодов

**Проблема.** Индекс слова зависит от токенизатора. WhisperX считает `don't` одним словом,
другой токенизатор — двумя; числа, дефисы и кавычки дают сдвиг, и вся подсветка «уезжает».

**Решение.**
- Токенизатор живёт в `mpt-core` (Unicode word segmentation + языковые правила для апострофов и дефисов).
- Компилятор присваивает каждому слову ID вида `s{N}.w{M}` (предложение/слово), уникальный в
  пределах урока: предложения нумеруются сквозь все блоки `reading` урока.
- Вывод внешнего выравнивателя (WhisperX / stable-ts / MFA — команда настраивается) сопоставляется
  с токенами **выравниванием последовательностей** по нормализованным словам (Needleman–Wunsch /
  diff), а не по индексу. Несовпавшие токены интерполируются по соседям.
- Компилятор печатает отчёт о покрытии и **падает**, если покрытие < 95% (порог настраивается).
- Ручные правки — в `timings.override.yaml`, который не перезаписывается при повторном выравнивании.
- Таймкоды хранятся прямо в скомпилированном AST (`"t": [start, end]` у токена).

## ADR-06. Словарь (lexicon) уровня курса и стабильные идентификаторы

**Проблема.** `meta.json` у каждого текста дублирует слова между уроками; ключ `knight` не
различает значения (`lead` — глагол и металл); прогресс ребёнка привязан к нестабильным ключам.

**Решение.**
- `lexicon/*.yaml` на уровне курса; урок ссылается на элементы по ID.
- ID элемента: `[a-z0-9-]+` уникален в курсе; для омонимов — суффикс значения (`lead-verb`, `lead-metal`).
- Глобальный UID: `{course_id}/{entry_id}`; `course_id` — reverse-DNS (`org.example.english-a1`).
- Типы элементов (`kind`): `word`, `phrase`, `term`, `formula`, `constant`, `law`, `definition` —
  именно так «активный словарь» обобщается на математику и физику.
- Переименование — через `aliases: [old-id]`, чтобы прогресс мигрировал.

## ADR-07. Шаблоны карточек по типу элемента

**Решение.** Для каждого `kind` есть набор шаблонов карточек (`recognize`, `recall`, `listen`,
`formula_meaning`, `meaning_formula`, `cloze`…). Карточка = (профиль, элемент, шаблон). Шаблоны
превращаются в `QuizItem` в Rust — SRS-сессия использует тот же `QuizRunner`, что и уроки.

## ADR-08. FSRS с автоматической оценкой

**Проблема.** Дети не умеют честно выбирать «Трудно/Хорошо/Легко».

**Решение.**
- Крейт `fsrs` (open-spaced-repetition/fsrs-rs). Burn в нём теперь только тестовая зависимость,
  поэтому для планировщика он подходит. Версию фиксировать в `Cargo.toml`.
- Оценка (`Rating`) **выводится из результата упражнения**:

| Исход | Rating |
|-------|--------|
| неверно / «не знаю» | Again |
| верно, но с подсказкой или со 2-й попытки | Hard |
| верно | Good |
| верно и быстрее медианного времени ребёнка по этому шаблону | Easy |

- Для старшего уровня UI родитель может включить ручные кнопки.
- Повтор ошибок внутри сессии (short-term) делает сессия, а не FSRS: ошибочная карточка
  возвращается через 3–5 карточек.
- Полный `review_log` хранится для будущей оптимизации параметров.
- Лимиты в день (новые/повторения) — настройка профиля.

## ADR-09. SQLite через `rusqlite`

**Проблема.** Макросы `sqlx` с проверкой запросов на этапе компиляции требуют `DATABASE_URL` или
offline-кэша (`cargo sqlx prepare`) — лишнее трение для агентов и CI; асинхронность для
локальной SQLite не нужна.

**Решение.** `rusqlite` (feature `bundled`) + `rusqlite_migration`. Одно соединение для записи за
`Mutex` в состоянии Tauri; тяжёлые операции — в `tauri::async_runtime::spawn_blocking`.
WAL-режим, `foreign_keys = ON`. Миграции только вперёд, нумерованные SQL-файлы.

## ADR-10. Типизированный контракт Rust ↔ TypeScript

**Решение.** `tauri-specta` + `specta` генерируют `src/lib/ipc/bindings.ts` (типы, команды и
события). Пакеты всё ещё в RC, поэтому версии фиксируются точно (`=2.0.0-rc.N`). CI проверяет,
что сгенерированный файл актуален (`just gen && git diff --exit-code`). Конкретные версии и
механизм генерации — ADR-23.
Fallback, если `tauri-specta` заблокирует обновление Tauri: `ts-rs` для типов + ручные обёртки команд.
Ошибки — единый `AppError { code, message, details? }`, сериализуемый в TS-union по `code`.

## ADR-11. Граница фронтенда

**Решение.**
- Фронтенд не обращается к ФС и SQL: только сгенерированные команды из `src/lib/ipc`.
  Импорт `@tauri-apps/api/core` вне `src/lib/ipc/` запрещён правилом линтера.
- Медиа: Rust возвращает абсолютные пути внутри каталога курсов, фронтенд превращает их в URL
  через `convertFileSrc`. Asset-scope ограничен `$APPDATA/courses/**`.
- Плагины `fs` и `shell` фронтенду не выдаются в capabilities.
- **Разрешённое исключение:** чистые вычисления над пикселями и геометрией UI (покрытие
  раскраски, сглаживание штриха) — в TS (Web Worker) с unit-тестами. Гонять растры через IPC дорого.

## ADR-12. Аудио: формат и воспроизведение

**Проблема.** Ogg Opus в WKWebView поддерживается только с iOS 26; WebM Opus — с Safari 17.4, и
с известной ошибкой при воспроизведении из Blob URL. На Linux аудио через `asset://` зависит от
плагинов GStreamer и исторически ломалось на перемотке.

**Решение.**
- Формат в пакете — **AAC-LC в `.m4a`**, моно, 48–64 kbps (речь), нормализация громкости
  (EBU R128, около −16 LUFS). Компилятор перекодирует любые исходники через `ffmpeg`.
- Воспроизведение — `HTMLAudioElement` (нужны `playbackRate` с `preservesPitch` для замедления
  0.75×), подсветка через `requestAnimationFrame` + бинарный поиск по таймкодам.
- В Фазе 0 — **спайк** на трёх ОС: воспроизведение, перемотка, `ended`. Если `asset://` на какой-то
  платформе ненадёжен, загрузка через `fetch` → Blob URL (аудио урока — единицы мегабайт).
- Документация для Linux: зависимость от `gst-plugins-good` / `gst-libav`.

## ADR-13. TTS: каскад без тяжёлых моделей на клиенте

**Решение.**
- Трейт `TtsProvider`; каскад: (1) аудио слова из курса → (2) кэш облачного TTS → (3) облачный
  TTS (Фаза 6, опционально) → (4) системный синтезатор (крейт `tts`).
- Приложение проверяет наличие голоса для языка и показывает предупреждение в настройках, если голоса нет.
- Пословная подсветка в MVP есть только для записанного аудио с таймкодами. Для TTS — подсветка
  предложения целиком.
- `whisper-rs` в клиент **не включается**. Выравнивание — задача компилятора курса.

## ADR-14. Единая модель упражнений и экзаменов

**Решение.**
- `QuizItem` — tagged union по `type`: `single_choice`, `multi_choice`, `type_answer`, `assemble`,
  `match_pairs`, `numeric`, `listen_choose`, позже `draw_shape`, `trace`, `color_region`.
- У каждого `QuizItem` есть `targets: [entry_id]` — связь с элементами словаря для SRS и статистики.
- **Проверка ответа — в `mpt-core::check_answer`**, а не во фронтенде. Нормализация: регистр,
  пробелы, `ё→е`, типографские апострофы и кавычки, список `accept`; для чисел — допуск и единицы.
- Экзамен = `ExamSpec`: пулы (`from` + `pick`), `seed`, `shuffle`, `pass_ratio`, `time_limit`.
  Отдельных форматов `minor_exam.json` / `major_exam.json` нет: есть `kind: minor | major`.
- Источник вопроса (`course | exam | review | ai`) пишется в попытку, но на UI не влияет.

## ADR-15. Профили, уровни интерфейса, родительский режим

**Решение.**
- Несколько профилей детей на устройстве; выбор профиля аватаркой, без пароля.
- **Родительский шлюз** (простой арифметический вопрос или PIN) для: настроек, API-ключей,
  импорта и удаления курсов, сброса прогресса, экспорта.
- Уровни UI профиля: `junior` (6–8 лет: голосовые инструкции, иконки, минимум текста),
  `middle` (9–12), `senior` (13+: плотнее, ручные кнопки оценки).
- UI-требования: зоны нажатия ≥ 48 px, шрифт по умолчанию **Andika** (SIL; спроектирован для
  начинающих читателей, покрывает латиницу, кириллицу и IPA), опция повышенного контраста,
  отключаемые анимации (`prefers-reduced-motion`).
- Альтернативный шрифт **OpenDyslexic** (решение человека 2026-11-26) — выбирается в настройках
  профиля, по умолчанию выключен. Это опция комфорта, а не лечебное средство: исследования не
  показывают устойчивого выигрыша в скорости чтения, поэтому дефолт остаётся Andika. Шрифт
  поставляется локально (woff2) со своим файлом лицензии. Если в нём нет кириллицы или IPA,
  недостающие символы берутся из Andika через стек `font-family`, а не из системного шрифта.
  Настройка шрифта применяется к тексту уроков и UI, но не к формулам KaTeX.
- Источники и версии шрифтов, sha256 и покрытие — `static/fonts/SOURCE.md` (Andika 7.000 из релиза
  SIL; OpenDyslexic 0.990 с forge.hackers.town по закреплённому коммиту — GitHub-релиз 2019 года
  без файла лицензии). Сабсетинг запрещён без переименования (Reserved Font Name в OFL).
- Экспорт и импорт прогресса профиля в файл (смена устройства) — уже в MVP.

## ADR-16. ИИ как опциональный, ограниченный провайдер

**Решение.**
- Трейт `LlmProvider` с реализациями: OpenAI-совместимый API (в том числе Ollama), Anthropic.
- Генерация только структурированных `QuizItem` по JSON Schema (из `schemars`). Ответ
  валидируется схемой **и** пост-фильтрами: все `targets` присутствуют, язык и длина в норме,
  ответ проверяется тем же `check_answer`, есть стоп-лист слов. Невалидное отбрасывается.
- В запрос уходят только слова и уровень. Имя, возраст в годах и другая личная информация не передаются.
- Лимиты: запросов в день, токенов на запрос, таймауты; кэш сгенерированного.
- Свободного чата для ребёнка в MVP нет. Сгенерированное помечается `source=ai`, родитель может
  пожаловаться на вопрос — тогда он исключается.
- Ключи хранятся за трейтом `SecretStore`: desktop — `keyring`; mobile — плагин безопасного
  хранилища (выбирается в Фазе 8).

## ADR-17. Песочница мини-игр

**Решение.**
- Игра — статический бандл в `games/<id>/` пакета курса с `game.json` (id, version, протокол, входные параметры).
- Отдаётся собственным протоколом `mptgame://` (обработчик в Rust) со строгим CSP: без сети, без `eval`.
- Встраивается в `<iframe sandbox="allow-scripts">` **без** `allow-same-origin`: непрозрачный origin,
  нет доступа к DOM родителя и к Tauri IPC.
- Общение — только `postMessage` по версионированному протоколу `GameBridge v1`; каждое сообщение
  валидируется схемой.
- Результат игры — это «заявка»: приложение проверяет, что `learnedIds ⊆ targetIds`, очки в
  допустимом диапазоне. Игра не может записать произвольный прогресс.
- Обязательный тест безопасности: из игры недоступны `window.parent.document`, `__TAURI_INTERNALS__`, `fetch` наружу.

## ADR-18. Безопасный импорт и обновление курсов

**Решение.**
- Распаковка: защита от zip-slip (нормализация путей, запрет `..`, абсолютных путей и симлинков),
  лимиты на суммарный размер, размер файла, число файлов и коэффициент сжатия; белый список расширений.
- Проверка `manifest.json`: `format_version` поддерживается, `min_app_version` ≤ текущей,
  SHA-256 всех файлов совпадают.
- Атомарная установка: распаковка во временный каталог → валидация → `rename` в
  `courses/<course_id>/<version>/` → переключение активной версии в БД → удаление старой.
- Обновление сохраняет прогресс: элементы с тем же UID сохраняются; исчезнувшие получают
  `status = retired` (карточки скрыты, не удалены); `aliases` переносят прогресс.
- Подпись пакетов (ed25519) — в бэклоге, поле в манифесте зарезервировано.

## ADR-19. Распознавание рисунков

**Решение.**
- Алгоритм **$Q** (многоштриховой, не зависит от порядка и направления штрихов) в `mpt-core`;
  шаблоны поставляются курсом (`templates/*.json`), поэтому буквы любого алфавита добавляются без кода.
- «Прописи» (`trace`): сравнение штриха с эталонной траекторией (допуск по расстоянию + покрытие).
- «Раскраска» (`color_region`): маски областей поставляются курсом, процент покрытия считается в
  TS Web Worker (исключение из ADR-11).
- Штрихи: `PointerEvent` + `getCoalescedEvents()`, `pressure`, `touch-action: none`; отрисовка —
  библиотека `perfect-freehand`.

## ADR-20. Локализация и многоязычный текст

**Решение.** Строки UI — Paraglide JS (типизированные сообщения, tree-shaking). Язык UI по умолчанию ru.
Инлайн-атрибут `lang=` в контенте ставит `lang` на span: правильные шрифты, переносы и голос TTS.
Paraglide 3 (T-001.3): стратегия `['localStorage', 'baseLocale']` (ключ `mpt.locale`; позже язык
задаёт профиль, T-406), `outputStructure: 'message-modules'`; код генерируется Vite-плагином и
`pnpm i18n`, в git не коммитится; плагин формата сообщений подключается локальным путём из
`node_modules` (без CDN, ADR-21). Смена языка перезагружает документ.

## ADR-21. Офлайн и приватность

**Решение.** Никакой телеметрии. Все данные локальны. Сетевые запросы — только к провайдерам,
которые явно настроил родитель. Логи — локальные, ротация, без личных данных.

## ADR-22. Определение MVP и порядок работ

**Проблема.** В исходном плане первый сквозной сценарий появляется только в конце, а
математика и английский требуют разных типов упражнений.

**Решение.** MVP (релиз 0.1) — **вертикальный срез**, проверяемый одним E2E-сценарием:
импорт эталонного курса → чтение урока (английский с караоке, математика с формулами и
терминами) → карточка слова/термина → «Изучать» → квиз урока → сессия повторения → перезапуск →
прогресс сохранён. Плюс профили, родительский шлюз и экспорт прогресса.

Не входит в MVP: планшет и распознавание, ИИ, облачный TTS, мини-игры, мобильные платформы.

Порядок фаз — в `docs/04_ROADMAP.md`. Сначала снимаются технические риски (спайки), затем
контракт данных, затем фичи.

## ADR-23. Фиксация toolchain, версий и механизма генерации контрактов

**Статус:** Принято (2026-11-26, план Фазы 0).

**Проблема.** `tauri-specta`/`specta` всё ещё в RC и требуют точного соответствия друг другу.
Вышла `tauri 3.0.0-alpha`, а у фронтенд-стека новые мажорные версии (SvelteKit 3, Vite 8,
TypeScript 6, Paraglide 3, Vitest 5). Node 20 из README снят с поддержки. Без фиксации агенты
в разных сессиях получат разные версии, и `just gen && git diff --exit-code` станет флаки.
Также не определено, *как* запускается генерация `bindings.ts` и схем.

**Решение.**
- **Toolchain:** `rust-toolchain.toml` с точной stable-версией (на 2026-11-26 — `1.100.0`,
  компоненты `rustfmt`, `clippy`), edition 2024, resolver 3. Node — **24 LTS** (`.node-version` и `.nvmrc` для nvm,
  `engines.node`), pnpm через `packageManager` в `package.json` (на 2026-11-26 — 12.x).
  Toolchain обновляется отдельным PR, а не попутно.
- **SvelteKit 3** не читает `svelte.config.js` (ошибка `config_file_unsupported`): конфигурация
  Kit передаётся в `sveltekit({...})` в `vite.config.ts`, `tsconfig.json` расширяет
  `$app/tsconfig`. Алиас `$lib` в Kit 3 удалён — импорты через `#lib/*` (`package.json`
  `imports`). В Vite 8 настройки HMR-сокета — `server.ws` (`server.hmr.*` устарел). TypeScript держится на 6.x (Kit 3 требует `^6`), переход на 7 — отдельным PR.
- **Lock-файлы** `Cargo.lock` и `pnpm-lock.yaml` коммитятся. В CI — `pnpm install --frozen-lockfile`.
- **Мажорные версии, сверенные 2026-11-26** (точные — в lock-файлах):

| Пакет | Версия | Правило |
|-------|--------|---------|
| `tauri`, `tauri-build`, `@tauri-apps/api`, `@tauri-apps/cli` | 2.x (2.12) | только Tauri 2; переход на 3.x — отдельный ADR |
| `tauri-specta` | `=2.0.0-rc.29` | точная версия |
| `specta` | `=2.0.0-rc.28` | точная, ровно та, что требует `tauri-specta` |
| `specta-typescript` | `=0.0.15` | точная |
| `rusqlite` / `rusqlite_migration` | 0.43 / 2.9 | `rusqlite_migration` 2.9 требует `rusqlite ^0.43` |
| `schemars` | 1.x | |
| `fsrs` | 7.x | фиксируется в T-402 |
| `tts` | 0.26 | последний релиз 2024-07: риск сопровождения, проверяется в T-004 |
| `svelte` / `@sveltejs/kit` | 5.x / 3.x | только runes |
| `tailwindcss` / `bits-ui` | 4.x / 2.x | |
| `@inlang/paraglide-js` | 3.x | |
| `vitest` | 5.x | |

- **Линты Rust** (`[workspace.lints]`): `unsafe_code = "forbid"`; clippy `unwrap_used`,
  `expect_used`, `panic`, `dbg_macro`, `todo` — `warn` (в CI `-D warnings`); `clippy.toml`:
  `allow-unwrap-in-tests = true`, `allow-expect-in-tests = true`. `clippy::pedantic` не включается
  целиком (шум); отдельные lint-правила добавляются по мере надобности.
- **Генерация (`just gen`)** — детерминированная, без запуска GUI:
  1. `bindings.ts`: бинарь `src-tauri/src/bin/gen_bindings.rs` (пакет `mpt-app`) вызывает
     `mpt_app::specta_builder()` (тот же builder, что регистрирует команды в `run()`) и
     экспортирует в `src/lib/ipc/bindings.ts`.
  2. `schemas/*.json`: подкоманда `mptc schema --out schemas/` (появится в T-101).
  `bindings.ts` и `schemas/` исключены из Prettier/ESLint, чтобы форматтер не создавал дифф.
  `just gen-check` = `just gen` + `git diff --exit-code -- src/lib/ipc/bindings.ts schemas/`;
  входит в `just check`.
- **Числа в IPC:** целые в DTO не превышают 2^53. Время в DTO — unix ms как TS `number`
  (`i64` экспортируется через явную аннотацию `specta`, способ фиксирует T-002). Идентификаторы
  `INTEGER PRIMARY KEY` в DTO — тоже `number`. `u64`/`i128` в DTO запрещены.

**Последствия.** Сборки воспроизводимы между сессиями агентов и CI. Обновление любой
RC-зависимости или мажорной версии — отдельный PR с прогоном `just check` на трёх ОС.

## ADR-24. Публикация, идентификатор приложения, лицензия, поставка GStreamer

**Статус:** Принято (2026-11-26, ответы человека на вопросы Q-1…Q-5 плана Фазы 0).
Пункт о GStreamer — предварительный: окончательно его утверждает T-004.4 по результатам спайка.

**Проблема.** Для каркаса (T-000, T-001) и CI нужны решения, которые после релиза трудно
изменить: видимость репозитория, bundle identifier (от него зависит путь `app_data_dir`),
лицензия кода, способ поставки декодера AAC на Linux.

**Решение.**
- **Репозиторий открытый** (публичный), хостинг — **GitHub**; лицензия подтверждена человеком: GPL-3.0-or-later. CI на ubuntu/windows/macos гоняется на каждом PR:
  стандартные раннеры GitHub Actions для публичных репозиториев бесплатны. В репозиторий не
  попадают секреты, ключи и личные данные (ADR-21); `.claude/settings.local.json` в `.gitignore`.
- **Bundle identifier — `dev.rnd-center.mpt`.** Не меняется после первого релиза: смена
  «теряет» данные детей в `app_data_dir`.
- **Лицензия кода — GPL-3.0-or-later** (SPDX). Именно GPLv3, а не v2: Tauri и значительная часть
  экосистемы Rust/npm распространяются под Apache-2.0, который несовместим с GPLv2-only.
  `LICENSE` в корне, `license = "GPL-3.0-or-later"` в `[workspace.package]` и в `package.json`.
  Зависимости — только с лицензиями, совместимыми с GPLv3 (MIT, Apache-2.0, BSD, ISC, Zlib,
  MPL-2.0, LGPL, GPL-3.0); проверка — `cargo deny check licenses` и аналог для pnpm в `just check`.
  Шрифт Andika (OFL-1.1) поставляется как отдельный компонент со своим `OFL.txt`.
  Лицензия контента курсов задаётся отдельно в каждом курсе (`02_COURSE_FORMAT.md`) и не
  наследует GPL.
- **GStreamer на Linux — поставляется вместе с приложением** (предпочтение человека). На Windows
  (WebView2) и macOS (WKWebView) AAC декодируется системой, вопрос касается только Linux.
  Основной Linux-артефакт — AppImage со встроенным медиафреймворком (опция бандлинга GStreamer в
  конфигурации AppImage Tauri; точное имя и состав плагинов сверить с документацией Tauri в
  T-004.4). Для `.deb`/`.rpm` — зависимости на пакеты с декодером AAC. Лицензии встраиваемых
  плагинов (LGPL) совместимы с GPLv3; список плагинов и их лицензий фиксируется в T-004.4.

**Последствия.** T-000 создаёт `LICENSE` и публичный remote; T-001.2 использует постоянный
identifier; T-001.4 добавляет проверку лицензий зависимостей; T-004.4 подтверждает или
пересматривает бандлинг GStreamer; T-408 собирает AppImage со встроенным GStreamer.
Ручная проверка на macOS пока невозможна (нет устройства) — macOS покрывается только CI до
появления устройства; ручной прогон на macOS обязателен до релиза 0.1 (T-408).
